# ADR-0026: Folder structure v2 — layers, feature manifests, absolute imports, enforced boundaries

Status: Accepted · Date: 2026-11-23 · Implemented on `refactor/folder-structure`

Amends the layout in [ADR-0003](0003-monorepo-layout.md). Source: owner request to make the
structure scale (easy to maintain, no duplicate code, common components in one place).

## Context

With 4 features the ADR-0003 layout worked, but it would not scale:

- `packages/features/src` mixed features with infrastructure (store, i18n, mocks, providers).
- Adding a feature meant editing shared files — store reducers, i18n resources, one mock-handler
  file, one analytics-events file — merge-conflict hotspots for parallel work.
- Features had no common internal layout.
- Both apps duplicated the root navigator / session guard and the list of top-level screens.
- `@starter/config` mixed dev tooling with runtime code that ships in the app.
- `@starter/ui` was a flat folder.
- Boundary rules ("only import a feature's index", "ui never imports features") were documented
  but not enforced; packages used deep `../../..` relative imports.

Options considered: keep the layout and add conventions only (cheap, but erodes as code grows);
split every feature into its own package (strongest isolation, much more setup per feature and
slower installs); **one features package with an app/ vs features/ split, manifests, aliases and
lint-enforced boundaries** (chosen — most of the isolation at a fraction of the cost).

## Decision

**Packages and layers** (an arrow means "may import"): `apps → features → api-client → core`,
`features → ui`, `apps → ui`. `@starter/config` is split into **`@starter/tooling`** (dev-only:
ESLint, TypeScript and Jest presets, path aliases, boundary rules) and **`@starter/core`**
(runtime: env, observability).

**`packages/features`**

- `src/app/` — infrastructure: `store/`, `providers/` (AppProviders, **RootNavigator**,
  ErrorFallback), `navigation/` (**destinations**, screen tracking), `i18n/`, `mocks/`,
  `testing/`, `feature.ts`, **`registry.ts`**.
- `src/features/<name>/` — standard layout: `screens/ components/ hooks/ api/ model/ services/
locales/ mocks/ analytics.ts types.ts feature.ts index.ts __tests__/` (only the folders needed).
- **Feature manifest:** `feature.ts` exports `defineFeature({ name, translations, slices,
mockHandlers })`. `app/registry.ts` lists the manifests; the root reducer, the typed i18n
  namespaces and the mock API are derived from it. Manifests live apart from `index.ts` so the
  registry never imports screens (no import cycles).
- **Shared navigation:** `app/navigation/destinations.ts` drives mobile's native tabs and the web
  sidebar / menu. **`RootNavigator`** (session guard) is shared; mobile passes `onReady` to hide
  its splash.
- `pnpm new:feature <name>` scaffolds a feature and registers it (marker comments in
  `registry.ts` and `src/index.ts`).

**`packages/ui`:** `tokens/ hooks/ primitives/ components/ layout/ testing/`.

**Apps:** `src/app/` routes only, `src/shell/` app-specific chrome (tabs, sidebar, splash-safe
error fallback).

**Absolute imports:** no `../`. Package-private aliases — `@app/*`, `@features/*` (features),
`@ui/*`, `@core/*`, `@api-client/*` — because Metro applies only the _app's_ tsconfig `paths`, so a
package-local `@/` cannot work. Source of truth `packages/tooling/aliases.js` (Jest); mirrored in
`tooling/tsconfig.base.json` (packages) and `apps/*/tsconfig.json` (Metro, apps). Verified with
tsc, Jest (packages and apps) and Metro bundles for iOS, Android and web.

**Boundaries enforced** by `no-restricted-imports` (`packages/tooling/eslint-boundaries.js`): no
deep `@starter/*/src` imports; aliases private to their package; layer rules; a feature uses
another feature only via `@features/<name>`; app code uses features only via their index (the
registry may import `@features/<name>/feature`).

## Consequences

- Adding a feature touches its own folder plus two marker lines (registry, package entry) —
  generated by `pnpm new:feature`.
- Layer and feature boundaries fail `pnpm lint` instead of eroding silently.
- Aliases must be kept in sync in three places (documented in `aliases.js`).
- `@starter/config` imports became `@starter/tooling/…` (dev) and `@starter/core/…` (runtime);
  older ADRs mention the old name.
- Rejected for now: a `core/storage` layer (token storage encodes auth policy and stays in the auth
  feature) and an empty `core/lib` folder (create it with the first shared helper).
- Pre-existing, unrelated: the home-screen test logs a Jest teardown warning (also on `main`).
